# 归档、刷新、第一节强提醒和复用课程

## 入口与默认行为

- 课程详情和课程操作菜单可归档本次课，或归档同一课程、同一学期中已经结束的课次；正在上课和未来课次不会被归档。
- 完成 DDL 后，在详情中选择归档。归档确认默认勾选“在课表与接下来中隐藏”。
- “设置 → 数据管理 → 归档”提供课程和 DDL 两类历史记录，支持单项和批量隐藏、重新显示、取消归档。课程默认合并为一栏，点击查看逐次历史。
- 设置中的归档分组新增“归档所有已结束课程”，跨课程与学期一次归档所有已结束且未归档的课次，默认隐藏，可在确认框取消隐藏。已归档、正在进行、未来及已删除课次保持原状态；没有符合条件的课次时给出提示。
- 归档页右上角设置可切换逐次显示、排序和拖动自定义顺序。课程合并、课程逐次、DDL 各自保留拖动顺序，新条目置顶。
- 自动归档默认关闭。课程和 DDL 的开关、延迟及隐藏偏好独立保存；启用后默认延迟 24 小时，运行中每分钟、启动、回前台和更改归档设置时检查。关闭应用期间，下次运行补处理。
- 取消归档的记录暂停自动归档；重新完成 DDL 或修改课程结束时间后，重新计算资格。
- “接下来”支持下拉刷新和标题栏刷新按钮，重新进入该标签也会刷新。课程结束时先划线，刷新后移除；刷新失败保留原列表。
- 强提醒配置新增“仅第一节课强提醒”。开关默认关闭，开启后的默认模式是课表第一节次；另一模式为 N 点前最早的一节课，N 默认 12:00。
- 第一节次优先使用导入记录中的节次，随后匹配作息方案；未知或有歧义的匹配回退到 N 点规则。学校第一节没有课程时，不将已识别的第二节误判为第一节。
- 明确指定强提醒或普通提醒的自定义规则仍优先，次日摘要不受第一节筛选影响。
- “设置 → 数据管理 → 调试”可立即测试强提醒；Android 另有一分钟后后台测试。测试使用独立提醒 ID，沿用当前声音、震动和持续时间，不改变正式配置。
- 单节和批量加课均可选择现有课程，包含仅有归档历史的课程。新课次关联原课程，历史记录不受影响；课程身份字段固定，可切换“新建课程”重新输入。

## 数据升级与发布

归档初次迁移为 SQLite v8／备份 v7；当前强提醒扩展后为 SQLite v9／完整备份 v8，详见 [强提醒与更新说明](orbit-strong-sync-updates.md)。旧记录和旧备份默认未归档、不隐藏。备份包含归档历史、显示和自动归档偏好。归档状态、课程关联与节次信息通过原有课程／DDL 同步实体同步；归档展示偏好仍为设备本地设置。

云函数新增保留旧客户端缺失字段的兼容处理，明确传入 `archivedAt: null` 的新客户端可以取消归档。发布新客户端前，应按 [CloudBase 部署说明](../cloudbase/README.md) 更新 `orbit-api` 及三个旧同步函数；共享源代码和各部署目录已保持一致。本次实现没有部署线上服务。

## 人工验收

1. 同一课程保留历史、正在上课和未来课次，执行整门课程归档，确认只处理历史课次，回收站为空，备份中仍有记录。
2. 对课程和完成 DDL 分别使用隐藏／不隐藏归档，验证两类列表中的批量显隐、取消归档、拖动及切换显示模式。未隐藏的归档完成 DDL 应能从课表日期入口查看完成状态。
3. 开启延迟为立即的自动归档，取消归档后等待一次检查，确认不会重复归档；再修改结束时间或重新完成 DDL，确认可再次自动归档。
4. 持续打开“接下来”等待课程结束，确认先划线，再下拉刷新，课程退出列表；网格和历史数据仍保留。
5. 分别使用有节次、仅有时间、多个作息方案、无上午课程及最早时刻冲突的课表验证第一节筛选，非首节仍有普通提醒。
6. Android 实机验证立即强提醒，以及设置一分钟后台测试后锁屏／切回桌面的声音、震动、持续时间和停止操作。Windows 验证系统循环提醒及停止操作。权限未授权时应有明确反馈。
7. 从已归档课程添加单节和批量课次，确认新记录未归档、原配色和课程级提醒仍关联，重复保存及冲突跳过／覆盖行为正确。
8. 在两个设备间同步归档和取消归档，并验证旧客户端编辑其他字段不会清除归档元数据。

自动化覆盖数据库迁移、备份往返、两个本地数据库间的同步应用、归档资格、提醒筛选、刷新缓存、表单复用及三种语言窄屏布局。平台构建和 Windows 原生队列测试不能代替 Android 实机锁屏、震动及后台播放验收。
