# 回到顶部定位与 WeMust 打卡入口

## 使用

设置 → 课表显示 → 回到顶部按钮位置：居左、居中、居右、智能。
旧设置默认使用智能；悬浮按钮和列表底部按钮均使用该选项。
智能模式属于持机方式估计，可随时改为固定位置。

智能模式使用最近 6 秒、最多 8 次手势，综合触点分布、滑动起止点、
轨迹弯曲、左右交替和分离的多指操作。最近四次手势提供主要方向依据。
至少连续两次稳定判断才切换，切换冷却为 1.5 秒；手指按住时保持原位。
短暂不确定保留上次结果，持续 6 秒没有可靠证据则居中。
陀螺仪用于降低摇晃时的可信度，重力方向提供平放/持机的辅助信息；
传感器不能独立判断左右手。缺失传感器时仍可根据触摸估计。
Windows 鼠标、滚轮操作时居中。

Android 仅在智能模式、接下来页面当前可见且应用前台时以约 30Hz 监听。
进入其他标签、覆盖页面、进入后台或切换固定位置时停止监听。
采用普通运动传感器采样，不需要身体传感器或高频采样权限。
手势摘要和传感器值仅在内存中使用，不落盘、不同步、不上传。
位置选项本身随现有课表显示设置备份和同步。

点击打卡通知打开课程详情时，Android 显示“打开 WeMust 课表”。
其他课程通知和手动查看详情不显示此入口。尝试链接后始终保留
“未到课表？打开 WeMust”及手动打开课表的提示。
无法使用链接时尝试启动 WeMust；未安装和启动失败都有提示。
Intent 被接受只表示系统启动了目标应用，不证明已经到达课表或完成打卡。

## 安装包分析依据与边界

- 样本：`ReWemust/base.apk`，WeMust 1.13.1。
- SHA-256：`8a7725c535a17ba9ef70d4f9f444d96d6f38ce8ffa111105d69774151695ec14`。
- Manifest：包名 `cn.doocom.wemustcampus`。
- Manifest：`cn.doocom.modulehome.deeplink.ServiceDeepLinkActivity`
  为 exported，接受 ACTION_VIEW/BROWSABLE，scheme `wmstud`、host
  `must.edu.mo`、pathPrefix `/services/`。
- `assets/modules/services.json`：学生服务代码
  `S-WM-CLASS-TIMETABLE-APP`，名称“課表”/“Class Timetable”，入口 `index.html`，
  模块版本 6.14.2。对应 HTML/JS 资源确实随包携带。
- 首个候选 URI：`wmstud://must.edu.mo/services/S-WM-CLASS-TIMETABLE-APP`。
  完整地址的参数格式是根据上述两项线索推断；尚未取得原生路由解析证据。
- 样本使用 `com.Proxy.ShellApplication` 加固，现有静态 DEX 无法还原该路由类。
  分析使用现有 aapt、JADX 和 ZIP 读取，不安装或执行截图中的工具初始化指令。

实现始终限定目标包，不请求无障碍、定位或蓝牙权限，不接管 WeMust 登录和打卡。
若后续 WeMust 版本更改入口，可在独立启动服务中调整 URI。
