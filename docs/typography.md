# 字体设置与启动衔接

设置 → 外观 → 字体：应用界面与开屏字标分别选择、预览并确认。
启动动画设置页也可进入字标选择。默认界面沿用原有平台字体链：
Android 使用 Flutter／平台默认字体，Windows 中文使用微软雅黑 UI；
开屏默认 Nunito。系统默认不保证跟随 Android 厂商主题商店的字体替换。

## 内置与导入

- 资源圆体 0.990：CN 常规、粗体，约 30,887 个编码；
  [官方来源](https://github.com/CyanoHao/Resource-Han-Rounded/releases/tag/v0.990)
- jf open 粉圆 2.1：常规，约 11,988 个编码；
  [官方来源](https://github.com/justfont/open-huninn-font)
- 荆南麦圆：官方仓库 TTF 常规，约 17,491 个编码；
  [官方来源](https://github.com/maoken-fonts/KNMaiyuan)

字体均按官方 SIL OFL 1.1 发布，版权及许可随资源打包，并加入应用许可页。
Nunito 继续仅作为原字标选项。中文字体覆盖范围各有差异，非系统选择优先
回退资源圆体，再由系统完成缺字及 Emoji 回退。图标字体不参与替换。

TTF、OTF（包括可变字体）每个最多 50MiB；不接受 TTC、网页字体或压缩包。
检查 SFNT 签名、表目录、边界和必要表，再注册到 Flutter 字体引擎；
失败时撤回新文件并保留当前设置。注册名称按内容 SHA-256 隔离。
文件以哈希命名保存在应用支持目录 `fonts/`，不依赖用户原文件位置。
重复导入复用文件；字体库可重命名、删除。删除使用中的字体时，受影响的
界面选择恢复系统默认，字标恢复 Nunito；未使用它的另一项不变。

系统通知、键盘和系统文件选择器使用系统自己的字体；本功能调整 Orbit 界面。
现有字号、字重、系统文字缩放继续有效，单字重字体可合成粗体。

## 状态、加载及恢复

`TypographySettings` 保存两套选择及导入字体目录；`FontService` 统一完成
结构校验、导入、按进程缓存和加载。初始化与数据库等启动工作并行，
应用首帧前加载当前字体；未选择的内置字体只随包存储，不预载。
切换时先完成加载再保存和发布状态，避免界面先换字再回退。
缺失、损坏或无法加载时按作用范围回退，并通过非阻断提示提供字体设置入口。

完整备份 v11 在设置中保存两套选择及正在使用的字体元数据，`fonts` 字段携带
按哈希去重的原文件；未使用的字体库文件不打包，不保存绝对路径。
最多两份、合计 100MiB 的字体数据随 JSON 备份或 `.orbit` 包迁移。
对应 `.orbit` 中 `backup.json` 的上限扩展为 256MiB，以容纳字体 Base64 与现有音频。
恢复先验证数据、安装新字体，随后在原有恢复事务中应用偏好；失败回滚新文件
与偏好。仅恢复课程不安装或选择字体。v1–10 缺少字体设置时保留本机选择。
字体选择及二进制都排除在云同步之外，不更改现有云端接口。

## Android 12+ 启动画面

原生 `windowSplashScreenAnimatedIcon` 直接引用方形 launcher 图片，已改为专用
圆形透明资源，两种亮度主题一致。原生 normal window 初始底色改为启动底色，
避免 Flutter 初始化期间出现额外黑／白底。首帧前预解码默认及已选启动图片，
Flutter 图标不再从完全透明开始；字标依旧淡入，图标中心不受字型度量影响。
自选图片与自定义字体只影响 Flutter 品牌画面，系统阶段仍使用静态资源。
系统桌面进入启动屏之前的图标缩放由系统控制，不作绕过。

测试覆盖真实内置字体、可变 TTF、CFF OTF、格式与大小限制、去重、独立选择、
删除恢复、缺失回退、备份去重／损坏／回滚、旧备份，以及三语窄宽屏大字体。
Android 12+ 冷启动、热启动、厂商桌面及通知启动的实际衔接仍需真机验收。

2026-10-17 验证记录：完整 Flutter 回归 741 项通过、1 项跳过；最终字体和
设置恢复相关测试 30 项通过；格式与静态检查无问题。Android 通用 Profile
APK（ARM64、ARMv7、x86_64）和 Windows Profile 构建成功，字体与许可文件
均与源码逐字节匹配。使用实际中文字库检查了预览排布。没有连接 Android
真机，不将这些结果视为厂商桌面启动动画及冷／热启动的视觉验收结论。

发布验证：Android 通用、ARM64、ARMv7、x86_64 Release 与 Windows x64 Release
均已重新构建，版本为 1.6.0+30，采用正式云同步编译配置。四个 APK 的版本、
架构、字体及许可匹配，签名与 v1.5.7 一致；Windows 原生自检通过，ZIP 的
45 个文件与构建输出逐字节一致。最终大小及 SHA-256 见发布更新清单。
