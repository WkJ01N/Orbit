# Orbit 1.5.3+25 强提醒、同步范围与更新

## 用户入口

- 设置 → 提醒 → 强提醒：两道加减心算或两轮 1–6 顺序点击，准备时间 5–60 秒（默认 15），答题时间 10–120 秒（默认 30）。每轮响铃沿用声音、震动和时长设置，默认 30 秒；最多三轮、间隔 15 秒，首次触发后的总期限固定。静音时轮次时钟继续运行，重进及重试不会延长总期限。
- 点击通知或打开应用先由原生层暂时静音；答题完成停止整个会话。退出、超时恢复提醒；长按 5 秒紧急停止及达到上限均记为未确认。并发强提醒共享确认任务。调试测试走相同流程，停止测试仅清除测试记录。
- 接下来、课表卡片与详情的时间栏显示本机实际配置下的强提醒标识，复用调度筛选和自定义规则优先级。
- 设置 → 账号与同步 → 同步内容：课程、DDL、模板、学期、作息默认同步；外观、配色、课表展示、普通提醒、自定义规则、强提醒及归档偏好默认关闭。无需账号即可使用强提醒。
- 默认每台设备独立选择范围；账号统一设置需联网成功后生效。切回独立模式恢复此前本机范围。新启用类别先预览含删除标记的完整合并；共享范围由其他设备启用时，显示待合并入口，确认前不接收该类别。关闭类别保留数据并暂存其待发修改。
- 设置 → 检查更新：每日启动／回前台自动检查，可关闭；手动检查不受间隔限制。确认提醒期间延后提示。支持自动测速和手选镜像、下载进度、取消和重试。安装前验证官方大小和 SHA-256。Android 使用系统安装页面，Windows 打开 ZIP 并提示退出解压替换。

## 原生状态与本机设置

Android 会话持久保存在独立原生 SQLite，提醒服务在 `:reminders` 进程推进绝对期限，应用创建 Flutter 引擎前发出静音动作。Windows 后台工作进程及每用户计划任务使用 `%LOCALAPPDATA%/Orbit/reminders/strong.json` 保存会话，原子写入与命名互斥锁保护跨进程更新。

业务数据库升级到 SQLite v9，完整备份 v8，旧记录及设置补默认值。账号凭证、设备同步范围、更新下载偏好、权限和运行中的答题状态不作为普通设置实体上传。声音只上传平台、来源类型和名称等描述；Android 同平台唯一匹配系统声音名称后恢复，否则回退默认声音并提示重新选择。本地文件路径不上传。

## 云端部署

客户端构建不部署云函数。本次需要按 `cloudbase/README.md` 的现有流程运行 `cloudbase/prepare-functions.ps1`，部署 `orbit-api` 以及保留的旧同步函数。新增文件 `sync-policy.js`、`updates.js` 要与 `orbit-api/index.js` 一起部署。

新增集合由 API 初始化机制创建：`orbit_sync_policy`（账号范围及修订号）与 `orbit_update_cache`（公开更新缓存）。延续现有服务端访问权限，客户端不直接写策略或缓存集合。新接口：

- `GET /v1/sync/policy`：获取账号范围。
- `PUT /v1/sync/policy`：通过 revision 比较原子保存；冲突时需刷新再保存。
- `GET /v1/updates/latest`：无需登录，15 分钟缓存 GitHub 正式发布及官方更新清单，客户端可回退 GitHub API。
- 同步请求新增 `supportsSettings` 与 `selection`；未知能力的旧客户端不接收设置实体。未升级服务器时原五类继续工作，新的设置同步需服务器升级。

## 发布

官方元数据来自 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases)，仅正式版本。发布工作流及本地工具 `python tool/generate_update_manifest.py release/v1.5.3` 在打包后生成 `update-manifest.json` 和 `SHA256SUMS.txt`，包含版本、构建号、平台包名、实际大小及 SHA-256。将清单与两个安装包一起上传到对应正式 Release；缺少官方校验信息时客户端不会提供安装入口。

镜像测速使用同一安装包最多 64 KiB 的范围请求，每源三次、取首字节时延中位数，单次 6 秒超时、最多两个源并发。镜像仅参与下载，文件校验信息仍来自官方渠道。
